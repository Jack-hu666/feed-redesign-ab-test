# Power BI 看板搭建说明

数据源：把 `sql/02_user_metrics.sql` 的用户级指标导出成 CSV/直接连库，导入 Power BI。三张页面：

---

## 页面 1：实验总览页（给管理层看结论）

| 组件 | 说明 |
| --- | --- |
| **指标卡 × 4** | 核心指标 CTR、停留时长、跳出率、加载失败率；每张卡显示「实验组 − 对照组」的差异值和方向箭头 |
| **切片器** | 实验日期、设备（iOS/Android）、活跃度（高/中/低） |
| **柱状图** | 对照组 vs 实验组 CTR 对比（带误差棒）|
| **卡片图** | 结论摘要：「建议全量上线」，核心指标显著、护栏未变差 |

关键 DAX（指标差异）：

```dax
CTR = DIVIDE(SUM(事件[click_cnt]), SUM(事件[expose_cnt]))

CTR差异 =
VAR c = CALCULATE([CTR], 用户[group] = "control")
VAR t = CALCULATE([CTR], 用户[group] = "treatment")
RETURN t - c
```

---

## 页面 2：分群效果页（给分析师看谁受益）

| 组件 | 说明 |
| --- | --- |
| **切片器** | 活跃度、设备、城市 |
| **横向条形图** | 各活跃度分群的 CTR 提升（pp），标注是否显著 |
| **分组柱状图** | 各设备分群的 CTR：对照组 vs 实验组 |
| **表格** | 分群明细：样本量、对照/实验 CTR、提升、p 值、显著性标记 |

目的：验证收益是否集中在高活用户，回答「全量上线还是先灰度某个人群」。

---

## 页面 3：时序趋势页（给运营看走势）

| 组件 | 说明 |
| --- | --- |
| **切片器** | 日期范围、指标切换（CTR/停留时长/跳出率）|
| **折线图** | 每日 CTR 趋势（对照组 vs 实验组两条线）|
| **折线图** | 每日停留时长趋势 |
| **面积图** | 累计样本量增长曲线（看是否达到目标样本量）|

目的：观察效应是否随时间稳定（有无 novelty effect / 波动），辅助判断是否需要延长实验。

---

## 数据模型（简单星型）

- 事实表 `事件表`：session_id、user_id、event_type、click_cnt、expose_cnt、duration_sec
- 维度表 `用户表`：user_id、group、activity_level、device、city
- 关系：用户表(1) —— 事件表(*)，按 user_id 关联
